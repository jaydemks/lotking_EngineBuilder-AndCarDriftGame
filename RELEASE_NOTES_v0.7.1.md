# Release Notes: v0.7.1

## Lot King Engine Builder v0.7.1 - Pawn Studio, Soccer Gameplay and Cross-Platform Authoring

### Release status

- Status: released.
- Tag: `v0.7.1`.
- Runtime baseline: Three.js `0.185.1` / revision `185`, Cannon.js `0.6.2`.
- Scope: Character/Soccer Pawn authoring, source-preserving FBX import, independent animation sets, isolated Pawn testing, soccer gameplay, cross-platform browser stability, adaptive startup preparation, vehicle effects, the native **Drift Track generator** and portable web export.

### Highlights

- Introduced Pawn Studio with per-motion GLB/FBX animation sources, Mixamo retargeting, Edit Rig corrections and isolated Pawn testing.
- Expanded the browser engine from its mature car-racing/drift foundation with composable Soccer Pawns, a physical ball/goal system and a playable penalty-shootout template.
- Added default-enabled FBX, Cloth Studio and P2P/coworking plugins while preserving portable WebGL and static playable exports.
- Completed the Three.js r185 follow-up across animation, rendering, post-processing, local addons and export packaging.
- Improved macOS/Safari startup, project recovery, LAN testing, DEMO publishing and cross-browser storage behavior.
- Added an opaque pre-benchmark that prepares real runtime paths, reports progress and recommends a reversible Low video profile on devices that remain below 25 FPS.

### Pawn Studio and character assets

- Added **Pawn Studio**, a reusable three-pane authoring overlay with a typed container tree, isolated Three.js viewport and contextual properties. Character, Soccer and Vehicle are built-in adapters; plugins can register further Pawn categories such as animals, boats or aircraft.
- Added the default-enabled **Cloth Studio** plugin for Character and Soccer Pawns. It authors separated skinned garments with automatic discovery, vertex-color/top-band masks, direct viewport pin/free painting, wind/gravity/quality controls, mesh diagnostics and automatic or explicit bone-sphere colliders. The saved component is shared by Pawn Studio, Play Preview and playable export.
- Cloth simulation uses a renderer-independent component and a deterministic CPU Verlet backend so the same project remains functional on WebGL and Safari. The official Three.js WebGPU compute-cloth example and the MIT-licensed `three-simplecloth` workflow are credited design references; WebGPU selection remains an authored preference and reports the portable backend until the engine-wide WebGPU path reaches feature parity.
- Character Main Mesh is now an explicit authoritative GLB/FBX-derived asset. It can be replaced without retaining the primitive dummy and reset to the built-in procedural T-pose without deleting its Motion Animation Set.
- Added **Normalized character height** and **Uniform world scale**. The same authored values are used by Pawn Studio, the Logic Element viewport, main editor, Play Preview and exported runtime.
- Rebuilt the procedural humanoid as a clean T-pose and retained procedural idle/walk/run/action feedback when no rigged Main Mesh is assigned.
- Added a second procedural fallback for an assigned humanoid/Mixamo Main Mesh: target-rest-relative clips now cover Idle, Walk, Run, both strafes, Jump/Land, Shoot/Pass/Cross/Tackle, goalkeeper ready/catch/left-right dive, Celebrate, Defeat and Interact. Pose axes are converted from character space into each bone's actual rest-local space, preventing Mixamo FBX/glTF bone-axis differences from turning a knee bend into leg twist; neutral Idle keeps the authored rest-pose legs unchanged. Pawn Studio and Play use the same rotation-only clips, imported animation assets always override them, and Main Mesh scale/position are never animated.
- Removed the old Camera helper from Character and Soccer spatial contents. Camera remains Pawn configuration; balls, goals, weapons and other interactions remain separate modular Logic Elements and no longer enlarge the Pawn dummy.

### Motion Animation Set and Mixamo

- Added a data-driven Motion Animation Set: every motion has its own state, direction, nominal speed, tolerance, priority, loop flag, playback rate, clip and optional independent GLB/FBX source.
- Added multi-file and folder import for animation batches. Filename/clip heuristics propose editable idle, walk, run, backward, strafe, jump, fall, landing and action metadata.
- Added deterministic motion selection and weighted blending from physical state, local direction, speed, acceleration and author priority. Legacy `animations.*` slots remain readable and migrate into the new set.
- Added animation-only GLB support. A take can omit render geometry while retaining a real armature and animation tracks; Pawn Studio applies it to the Main Mesh instead of replacing the model.
- Added Three.js r185 `SkeletonUtils.retargetClip()` integration for compatible Mixamo/Blender naming variants and namespaces. Preview diagnostics distinguish invalid keyframes, zero bound tracks, static tracks and successful skeleton retargeting.
- Retargeted hip translation now uses corresponding bone-segment ratios in armature-local space and is rebased onto the Main Mesh rest position. Hip orientation is also rebased to remove FBX/glTF up-axis conversion, while horizontal root motion is made in-place and vertical jump/fall movement remains available. This keeps the outer uniform world scale as one final multiplier instead of counting it again in the retarget ratio. Independently normalized Mixamo files cannot override Main Mesh height, facing or proportions; an incomplete retarget falls back to rotations only instead of applying foreign bone position/scale tracks.
- Motion slots now persist a **Source orientation** preset shared by Pawn Studio and runtime. Direct Mixamo FBX defaults to Y-up; Auto derives corrections from the complete source/target bind poses, while manual ±Z-up, ±X-up and 180° facing presets handle non-standard exporters without a Blender round trip.
- Added a per-slot **Animation preview scale** override. Its `1×` default inherits Main Mesh height/world scale, while changing it affects only the isolated Pawn Studio viewport. Standalone FBX render meshes are automatically fitted instead of being shown in raw centimetre units.
- Standalone animated FBX previews now reject scale/bone-position tracks that overwrite bind-pose proportions and lock their fitted root transform after every mixer update. Preview scale accepts Italian decimal commas and values down to `0.0001×`.
- Character Play Preview now keeps the procedural Pawn visible until the canonical Main Mesh is renderable. Failed or missing GLB builds no longer leave an empty holder that suppresses the fallback; locally preserved FBX sources are attempted as an editor/runtime recovery path and failures remain visible through `characterModelError`.
- Motion-slot playback now uses the same canonical-GLB-first, preserved-FBX fallback as Pawn Studio. An Idle or action take that previews correctly from its FBX source no longer disappears silently when its runtime GLB derivative is unavailable.
- Final Play Preview rendering no longer hides `empty` Logic Element transform containers. Only their renderable editor helpers are filtered, so a Character root cannot make its Main Mesh, Idle pose and procedural fallback disappear together for a frame.
- Runtime retargeting now uses the normalized Main Mesh root, matching Pawn Studio instead of calculating against the outer world-transform holder. A rig-pose guard also rejects non-finite or explosively displaced animation results and restores the authored rest pose rather than letting the Character disappear.
- External runtime takes can no longer overwrite Main Mesh position, scale or visibility tracks. The authored model height and uniform world scale remain authoritative while animation drives rotations and morph targets, preventing centimetre-authored FBX clips from expanding the Character around the player camera.
- Pawn Studio and runtime now enforce the authored position and scale of every Main Mesh rig node after each mixer update, not only the outer model transform. Bone rotations remain animated, while FBX centimetre units can no longer enlarge the skinned hierarchy in either preview path.
- Hosted workspace setup now has a true browser-database path on every browser. Safari uses standard file input for LKEP import, while Chromium can optionally link a writable folder; browser mode also requests persistent storage and records quota diagnostics when the Storage API is available.
- LKEP files selected through the workspace are validated before the workspace mode changes, and import/storage failures are reported in the editor instead of escaping as unhandled Promise errors.
- The bundled DEMO is applied directly from its downloaded in-memory project instead of depending on a successful localStorage round trip, preventing partial WebKit storage writes from producing a broken or empty initial level.
- Apple Metal/WebKit renderers use a capability-driven conservative profile: Retina supersampling is capped and GTAO/SSR passes that produce unstable screen-space buffers on affected Apple WebGL drivers are not constructed. Authored PBR, shadows, tone mapping and portable WebGL rendering remain active.
- `avvio.bat` now exposes the project-aware server on the LAN by default and `serve_local.py` prints usable device URLs. Remote browsers keep isolated IndexedDB projects; host disk-backup and performance endpoints enforce a loopback-only HTTP boundary and return 403 over the LAN.
- The default-enabled **P2P Sessions & Coworking** plugin adds encrypted WebRTC DataChannels, temporary manual invite/answer signaling, paced large-message chunking for Safari, peer presence, single-authority live transforms and reviewed portable LKEP snapshots.
- Logic Elements add Network receive/send, connection status, session studio and disconnect nodes. The same session surface is included in editor preview, gameplay and playable exports.
- Every Projects row now exposes **★ DEMO**. The active row builds from the exact open scene and complete level set; another row publishes exactly that saved project. The result is validated and atomically written to `demo/demo-project.lkep.json` through a loopback-only endpoint while backing up the previous publication. LAN/hosted browsers receive the exact file as a download instead.
- The console policy filters Chromium extension message-channel shutdown noise in both `unhandledrejection` and captured `error` events, while leaving engine errors untouched.
- Playable export prefers persisted DB blobs over speculative filename probes, removing expected `HEAD media/images/... 404` noise for imported images such as GIF assets.
- Runtime character skinned meshes disable bind-pose frustum culling, preventing a valid retargeted model from disappearing in Play Preview when an FBX pose extends outside its imported bounds.
- Pawn Studio Play/Stop now owns a real `AnimationMixer` driven by `THREE.Timer`. Stop freezes the current pose; Play restarts the selected slot; preview speed `0.25×`–`2×` composes with the slot Playback Rate.
- Animated `SkinnedMesh` preview bounds are refreshed when framing and isolated preview disables frustum culling, preventing limbs from disappearing because of stale bind-pose bounds.

### FBX importer plugin

- Added the default-enabled, user-toggleable **FBX → GLB Importer** reference plugin.
- Original FBX files and the sidecar textures actually consumed by them are preserved as authoring sources in IndexedDB. `FBXLoader` provides direct source preview while `GLTFExporter` creates the linked canonical GLB used by gameplay and portable exports.
- Added multi-file/folder dependency resolution, TGA support, conversion progress/warnings, source/build provenance and grouped deletion of the source, compiled GLB and sidecars.
- Added **Check / relink FBX source** and **Rebuild runtime GLB**. A changed source becomes `STALE`; the last valid runtime GLB remains usable until rebuilding succeeds.

### Isolated testing and editor workflow

- The built-in `player_car (Logic)` is now an opt-in compatibility Pawn and starts completely inactive. Its Scene-sidebar eye activates or deactivates rendering, native physics body, input/Player-slot possession, camera, engine audio, lights, exhaust and tire effects as one coherent state; the inactive registry row remains available so it can be restored instantly while Vehicle Logic Elements take over normal authoring.
- Free Camera now enters its real orbit state on the first Play Preview/gameplay frame instead of advertising Free while retaining the old chase sub-state until the camera mode was cycled. Mouse look also recognizes the editor viewport before pointer lock; one click remains available for browser-native unlimited pointer capture, but is no longer required to initialize the camera.
- The standalone editor loading screen no longer flashes gameplay navigation after entering from the landing page. Choose Track, the duplicate Engine Editor action, menu music and the level picker stay hidden while the editor workspace loads.
- Character and Soccer Logic Elements now place their root exactly on the selected surface, so both the Pawn feet and its transform axis agree with the editor grid. Existing editor-created instances that still carry the old automatic 0.15-unit lift are migrated on load; intentional elevations and sloped template placement remain untouched.
- Pawn Studio Main Mesh settings now include live global Ground Y, Pitch, Yaw and Roll alignment sliders with numeric readouts and one-click reset. The correction is stored on the mesh holder outside the skeleton, so it consistently affects the Studio, editor, Play Preview and export without rewriting individual animation clips.
- Pawn Studio is now a transform-authoring viewport: Move, Rotate and Scale use Three.js axis gizmos (with W/E/R shortcuts) and persist the Main Mesh position, orientation and per-axis scale used by editor, Play and export.
- Motion slots add **Edit Rig**. The isolated viewport pauses the take, displays its real skeleton and attaches a local rotation gizmo to a selectable bone. Per-bone corrections are stored as a non-destructive pose layer for that slot and blended by the same runtime weights as Idle/Walk/Run/actions, allowing a crouched Idle to straighten naturally during the transition instead of shifting the entire character. Reset Bone removes one override; imported keyframes, positions and scale remain untouched. Legacy Flying Curve metadata stays preserved in existing project data but no longer shifts the runtime Main Mesh.
- Edit Rig correction maps are isolated per Motion entry: editing Idle cannot modify Walk, Run, Jump or actions. A correction contributes only through its own live animation weight and reaches zero when that state finishes blending out.
- Motion Set locomotion and the older fixed-slot controller are now strictly exclusive. Legacy Idle can no longer remain at full weight underneath Walk, Run or Strafe, removing the competing poses visible during turns and ensuring an Idle Edit Rig override never contaminates the Main Mesh or another state.
- Soccer movement adds an explicit **Facing Behaviour**. Its football default preserves heading so A/D produce true lateral strafing while W/S move forward/back; generic Characters can retain turn-toward-velocity movement. Both movement space and facing behavior are editable in Pawn Studio and exposed by the Soccer template.
- A real Motion Set `state: jump` now owns the airborne animation. The legacy/default Jump one-shot runs only when no authored Jump entry exists, preventing it from masking an imported Mixamo take.
- Pawn Studio saves now stamp a runtime revision on the Logic Element graph. The Logic runner includes that revision and the editor/game execution mode in its rebuild signature, so Main Mesh gizmo and Edit Rig changes cannot remain confined to the Studio preview while Play continues using an older Pawn instance.
- Gizmo authoring commits after drag inactivity as well as TransformControls mouse-up and Studio close. Saving now synchronizes the selected world instance and its embedded graph before updating any reusable linked definition, guaranteeing immediate Pawn Studio ↔ editor viewport parity even if linked-asset persistence is delayed or fails.
- The Logic Element Viewport now has **Play Isolated** for Character and Vehicle Pawns. Keyboard/touch input drives only the internal preview; Stop restores the authored transform and leaves the main world stopped.
- Pawn Studio preview requests are ordered. Rapidly selecting imported motion entries cannot let an older asynchronous load clear the newest model.
- Assets support Ctrl/Shift multi-selection and bulk deletion from the asset card, context menu or Delete command. Duplicate logical selections are removed once, together with linked FBX records.
- Retired the missing `models/player.glb` / `models/player/scene.gltf` startup probes. The procedural character is the intentional no-asset fallback, so normal editor boot no longer emits those 404 warnings.
- Logic Element cloning sanitizes runtime-only and circular `userData` before Three.js copies an object, fixing `Converting circular structure to JSON` during editor reconstruction.
- Native and Logic Element vehicles now emit tire smoke, skid marks and tire-scrub audio only while the relevant raycast wheels touch a surface. Airborne vehicles cool their tires instead of painting marks beneath themselves. Tire-smoke defaults now require sustained heat, meaningful slip and an appropriate minimum speed/angle; the new speed and drift-angle thresholds remain editable with the existing tire-effect controls.
- Native and Logic Vehicle exhausts now share expanded smoke controls for continuous/pulsed output, lifetime, opacity, growth, turbulence, temperature tint and velocity inheritance. Backfire is rendered as a short anchored flame cone aligned with each exhaust outlet, so it crackles at the pipe and disappears through an explicit lifecycle instead of behaving like persistent world-space smoke.
- Modern themed scrollbars now cover long Settings panels instead of falling back to the browser's legacy scrollbar styling.
- Loading Music, Gameplay Radio, Editor Menu music and Game Menu music are now independent ordered libraries. The index keeps Loading Music active while a destination is unresolved and switches only when the requested menu/runtime is ready. Menu-role Play/Preview suppresses radio, vehicle audio and gameplay HUD startup, selects the matching menu playlist and preserves its first-track order through Save, LKEP and playable export. Stop Preview keeps its fade-out but resets menu playback to the beginning, so the next preview starts from `0:00`. Radio and its TAB UI now default to Player 1's possessed native or Logic Element vehicle; the HUD inspector provides explicit Specific Actor and Global overrides. Older projects with one shared menu library still migrate into both menu roles.
- Every editor music library now has explicit Preview and Stop transport actions. The restored floating audio controller follows the currently previewed Radio, Loading, Editor Menu or Game Menu library, exposes volume/next/stop controls, and can always be reopened from the viewport `♪` button.
- Viewport Collision Dummies again displays every collider not explicitly marked hidden. Enabling it also restores the active viewport helper layer, while Play/Simulate continues to require the separate Force option.

### Visible runtime pre-benchmark and adaptive video

- Added a visible scene pre-benchmark before the editor becomes ready and before every gameplay or editor Play/Simulate session. An opaque presentation hides incomplete 3D content while the runtime prepares hidden-object visibility in bounded batches, authored lights and colors, dynamic shadows, physics, plugin warm-up hooks, configured post-processing paths and Three.js shader compilation.
- Shader preparation now uses one serialized renderer queue. WebGL deliberately uses the safe r185 synchronous compile path and then settles through real rendered frames; native `WebGLRenderer.compileAsync()` is reserved for WebGPU because its WebGL material polling can lose a replaced/disposed program, throw `isReady` outside its Promise and leave loading permanently at 72%. A failed warm-up becomes a controlled fallback instead of blocking editor entry.
- The benchmark restores every temporary scene, light and material mutation before handing control back to the user. Runtime systems can register bounded warm-up hooks without moving benchmark-specific behavior into the main composition root.
- Vehicle smoke and flame shader variants are included in pre-benchmark preparation, preventing their first gameplay emission from paying the full shader-compilation cost.
- A sustained rendered-frame sample selects a conservative profile when it remains below 25 FPS: Low quality, antialiasing off, WebGL renderer, dynamic shadows off, ambient occlusion off, reflections off and volumetric lighting off.
- Video controls remain authoritative. The first explicit user video change is stored as a manual override, so later pre-benchmarks report performance without forcing the automatic Low profile again.
- The landing screen now gives a concise full-project hardware recommendation and explains that editor, physics, asset and rendering systems run together in the browser.
- It proactively uploads authored GPU textures and adaptively renders controlled rear/side/up/down camera orientations after selecting the appropriate video profile, then restores the exact camera transform before fading out. Very slow profiles prepare the most important rear view first, while browser-hidden tabs skip throttled panorama work; this moves common first-look shader, geometry and texture stalls out of interactive editor/game camera movement without making slow-device startup unbounded.

### Character movement and level content

- The Scene eye is now a true activation switch for Logic Pawns. Hiding `player_car (Logic)` or another Pawn immediately releases its camera and Player slot, stops input/physics and disables its graph persistently; showing it recreates the Pawn from the same authored configuration.
- Pawn Studio now persists whole-animation position and rotation per Motion slot. Viewport gizmo edits and numeric values are applied identically in Play, blended with the Motion Set state, and remain isolated from Main Mesh and every other slot. The Play layer lives outside the imported GLB mixer, preventing an FBX/GLB root orientation from restoring the source inclination after Pawn Studio corrected it. Pawn Studio now previews the same canonical converted GLB hierarchy used by Play instead of silently using the original FBX with potentially different root axes or bind pose; external motion sources also remain unfitted until retargeting in both paths. Stationary Idle is exclusive at full weight from the first frame, while Edit Rig deltas are removed before mixer evaluation and reapplied afterward.
- Motion Set directional selection now gates direction before comparing gait speed. A straight Run no longer receives a small one-sided Strafe contribution when several candidates have similar metadata, while diagonal Forward/Strafe blending remains available.
- Pawn Studio adds per-slot **Root yaw** handling. Forward/backward Walk and Run samples automatically remove progressive Hips/root yaw while retaining authored pitch, roll and body motion, fixing FBX takes that visually steer during a straight Shift Sprint. `Locked` and `Authored` overrides cover non-standard locomotion and intentional turning clips.
- Free Camera is now the real initial Play camera for built-in Character, Soccer and Vehicle Pawn templates. Existing untouched template instances migrate from the former Arcade default once; an explicit camera choice made afterward is preserved.
- Added a dedicated **Sprint** action, remappable from Controls (`Shift` on keyboard, right bumper on gamepad). It no longer shares the vehicle Handbrake binding or conflicts with Jump.
- Walk/run choice follows Sprint state while analog input still controls magnitude within the selected gait.
- Added procedural placeholder locomotion and automatic upgrade to a bound GLB controller.
- Added **New Level → Penalty Shootout Stadium (Soccer)** with a regulation editable stadium and a professional five-element composition: possessed kicker, unpossessed goalkeeper, explicit penalty Ball, independent Goal Frame sensor and configured Penalty Shootout Manager.
- Fixed the penalty preset's exposed runtime bindings so its yellow unpossessed goalkeeper remains a goalkeeper in Play instead of being rebuilt as the red Player Pawn; existing generated penalty levels migrate automatically. Charged shots now visibly hold the authored leg at its wind-up pose, show a live physical flight trajectory while aiming and after contact, and let the goalkeeper either secure a controlled central shot in the animated hand position or physically parry harder/diving saves. Mouse aim is camera-correct on both sides, the reticle is projected from the real 3D target instead of using an unrelated HUD approximation, and **Show Aim Reticle** is an exposed Soccer Pawn option for authoring assisted or harder play. The kicker now turns toward the goal during the run-up and toward the selected target during charge, keeping body facing, animation and physical shot direction coherent.
- Added reusable **Template - Soccer Ball** and **Template - Soccer Goal Frame** Logic Elements. Classic play is composed from a free match Ball, two Goal sensors and any number of role-based Soccer Pawns; penalty play links striker, goalkeeper, locked Ball, Goal sensor and referee Manager through stable `BallId` / `GoalId` values. The Manager remains compatible with older scenes that relied on its internal runtime ball/goal creation.
- Corrected the Penalty Stadium presentation: the preset now starts at fixed noon with readable daylight, the referee no longer renders a debug cube, and the Soccer Ball has a regulation-size editor marker that is replaced by the physical ball in Play. Levels created with the first dark `.62` preset and its embedded Soccer template copies migrate automatically.
- Fixed CSS-authored material colors being coerced through `Color.setHex`, which could turn generated pitch markings, goals and stands black. The soccer preset now uses a green pitch, pure-white markings/posts and a coordinated blue stand palette; untouched instances from the first preset migrate to it.
- The generated physical Soccer Ball is now retained by final gameplay rendering instead of being mistaken for a non-exportable editor helper.
- Added configurable goalkeeper AI (`enabled`, reaction time and prediction window). An unpossessed keeper predicts the ball/goal-line intersection, chooses a catch or directional dive and recenters between attempts; possession by Player 2 suspends AI immediately.
- Gameplay HUD now follows the possessed Pawn context. Soccer hides vehicle speed/drift/tuning UI, shows penalty score/round/phase and football controls; generic Characters also stop exposing vehicle-only UI. Driving setup input is accepted only while a Vehicle Pawn is active.
- Hiding the native `player_car (Logic)` now also hides its editor camera frustum, rig and target line instead of leaving the camera helper behind.
- Completed the shared Soccer ball interaction layer. Match Pawns use soft non-welded nearby-ball control; shoot/pass/cross/tackle impulses occur at the animation's foot-contact phase and target the closest forward goal by default. Penalty Manager locks that same ball on the spot until a valid contact, then goal/save/out detection and reset continue through the existing referee flow. Ball control distance and shot/pass/cross power are exposed on the Soccer Logic Element.
- Replaced the one-tap penalty shot with a continuous football shot model: hold `F / X` to charge, aim horizontally and vertically with movement input, optionally hold Sprint for stronger curve, then release. Power, target height, bend and risk-based inaccuracy feed the existing ball gravity/Magnus physics, while the HUD shows live aim and charge.
- Penalty mouse/right-stick aim now begins in the Ready/Aim phase instead of only after charge starts. The reticle, stored shot target and visible Pawn heading remain synchronized, and pressing the shot button inherits the prepared direction. The Soccer HUD now reports `GOAL`, `SAVED` or `MISSED`, shows both teams' kick histories and makes it explicit that a save records an attempt without increasing the score.
- Added a persistent, project-agnostic **Easy / Medium / Hard** Gameplay difficulty. Soccer applies it to goalkeeper reaction, prediction error/window, tracking, physical reach and dive distance. Unpossessed outfield Soccer Pawns can enable **Field-player Opponent AI**, which uses the same difficulty for reaction delay, closing pace and shot error; the generic profile is reusable by future game categories.
- Saved Soccer instances that still contain the original `OnKeyDown F -> Play Soccer Action` path are now guarded at runtime as well as migrated: a held physical action begins charge and reads live aim until release, so an old embedded graph can no longer bypass the shot model with an automatic central kick. Soccer/editor/gameplay asset revision tags were advanced together to prevent browsers from retaining the previous runtime.
- Shot aiming now prioritizes mouse movement and the gamepad right stick while charging, with a visible goal reticle and integrated power marker. Keyboard axes remain a fallback. The horizontal goal basis was corrected so left input targets the visible left side and right input targets the visible right side.
- Browser builds now use a dedicated Cannon Soccer body for every ball: a regulation sphere with mass, damping and angular response collides against the ground, cylindrical posts, crossbar and the open rear/side/roof net bodies. Kicks and animated foot contacts apply impulses; gravity, contacts, rebounds and post deflections then come from the physics solver. The deterministic implementation remains only as a no-Cannon fallback.
- Ball engagement now samples the animated GLB/Mixamo foot bones when present, with a rig-independent fallback for placeholders. Match touches physically nudge the free ball; touching a locked penalty ball before completing the kick visibly moves it and records a miss instead of letting the player walk through it.
- Goalkeeper AI now commits to the generated catch/directional-dive action before interception. The stadium goal was rebuilt as a conventional front/rear frame with one open grid net; scored balls are damped and retained by the net volume, while the impact drives a lightweight local elastic ripple and damped return. The penalty-area “D” is now one smooth regulation-radius primitive, and existing untouched v2 penalty presets migrate to the v3 goal/marking set.
- Goalkeeper behavior now uses the registered goal's local coordinate system instead of assuming a north/south world axis. Before the shot it tracks the closest ball across a constrained part of the goal line; after contact it predicts time, lateral intercept and ballistic height, then selects a centered/high catch or a time-scaled directional dive and returns to its authored spawn between attempts.
- Corrected the two upper goal rails so they slope from the front crossbar toward the lower rear frame on both ends. The Penalty Stadium is now v4 and upgrades generated earlier rails automatically.
- Disabling the native `player_car (Logic)` is now an immediate full shutdown: camera helper/rig/line, exhaust and skid helpers, already-alive exhaust particles, test pulses, physics, input and audio are all removed or stopped synchronously. Hidden native cars reject new exhaust test emissions instead of leaving scene-level smoke behind.
- Character and Soccer Pawn migration now removes every legacy spatial Camera component embedded in the Pawn hierarchy. Pawn cameras remain runtime configuration only, preventing an old sideline `camera_anchor` from being mistaken for the hidden native car camera.

### Drift Track generator ("Minami Drift Park")

- Added a native, parametric **Drift Track** element that reproduces the standalone "Minami Drift Park" mini-game map exactly: same 17 catmull-rom control points and tension, asphalt ribbon, checkered start line, red/white curbs, tire walls, start portal banner, grandstand, trees, light poles and slalom/apex cones. The original generation code is ported to the engine Three.js r185 build instead of the mini-game's cannon-es prototype, so the geometry is identical.
- Wall and cone collisions are registered as **arcade box colliders identical to the original `CANNON.Box` bodies** (same half-extents, position and Y-rotation), giving pixel-accurate, drive-perfect boundaries. They are attached as a single compound collider (`ref.parts`) so the whole set follows the object transform and is cleaned up automatically when the track is deleted.
- The track is a first-class editable element: **Add → Level → Drift Track (Minami)** places the exact circuit, **Drift Track (random)** generates a brand-new closed circuit from a seed, and both save with the level like any editor content.
- Added a dedicated **DRIFT TRACK** inspector section: seed, road half-width, wall gap and tree count, per-component visibility toggles, wall/cone collision toggles, **Apply / Regenerate**, **Random layout**, and a JSON editor for the track control points. Tree scatter is now seeded and deterministic (the mini-game re-randomized it every load).
- Added a **New Level → Drift Track - Minami Drift Park** template with a large drivable apron and the player spawn placed on the track. The standalone mini-game car is intentionally not duplicated; the native engine player drives the circuit.
- The generator ships in `engine_editor.html` and `gameplay.html`; the playable exporter picks it up automatically from the runtime template, so exported games containing a drift track rebuild it correctly.

### Known limitations

- The editor remains experimental; keep versioned `.lkep.json` exports while working on this release.
- Browser security prevents silent monitoring of arbitrary FBX files. Source change detection requires the explicit relink/check action.
- Animation-only assets must retain a real armature and keyframes. A file containing neither mesh nor bones cannot be retargeted.
- Automatic retargeting covers compatible humanoid hierarchies and common exporter naming variants; genuinely different rigs still require a dedicated authored retarget profile.
- Character/Mixamo authoring is functional but remains an active experimental area; car racing and drifting are still the most complete ready-to-use gameplay path.
- Sprint has no dedicated touch button yet; the existing Handbrake tap is reused for on-foot Sprint.
- The goalkeeper AI is intentionally an arcade/predictive baseline. Projects needing tactical positioning, defender coordination or animation-specific motion matching should extend it through Logic.
- Drift Track cones are solid static obstacles (a faithful slalom challenge) rather than knock-over dynamic props as in the mini-game prototype. The track edits at the parameter/control-point level and as a whole transform; individual sub-pieces are not separately selectable, and duplicating the whole track does not re-register its wall colliders.
