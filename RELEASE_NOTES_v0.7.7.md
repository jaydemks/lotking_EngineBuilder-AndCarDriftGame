# Release Notes: v0.7.7

## Cinema Studio

- Added deterministic offline **Render video** export to Cinema Studio. Output is evaluated at exact `frame / FPS` timeline times, so a difficult 4K/post-processing frame can take as long as necessary without being skipped, duplicated or stretching the final footage timing.
- Added self-contained VP9/VP8 WebCodecs encoding and timestamped WebM muxing with HD, Full HD, QHD, 4K and vertical presets, timeline FPS, High/Master bitrate profiles, estimated size, live frame/ETA progress and cancellation.
- Reused the authored final scene and post-processing path while excluding helpers/dummies. Cameras and shaders are warmed first; each submitted GPU frame is awaited through an asynchronous WebGL2 fence before capture.
- Kept the already experimental Path Tracing renderer out of this first production-oriented footage path; when Path Tracing is selected, the export dialog states that it will use the stable final raster/post compositor.
- Offline export temporarily owns the shared renderer, then restores pixel ratio, canvas/composer size, viewport/scissor state, active preview time, animated object transforms and camera lens state after success, failure or cancellation. Existing runtime cinematics, gameplay triggers and cinematic menu backgrounds are unchanged.
- Kept this first frame-accurate path explicitly video-only. Deterministic audio rendering/muxing remains separate future work rather than recording wall-clock audio that could drift when frames render slower than realtime.

## Rendering performance

- Moved first-use Logic Vehicle work into the visible pre-benchmark. Cannon bodies and raycast wheels, light rigs, imported wheel/steering rigs, dashboard widgets, effect anchors and muted engine-audio graphs are now prepared before the first accelerator input.
- Made static-physics rebuilds signature-aware. Entering Play no longer rebuilds an unchanged triangle-mesh collider world immediately after the pre-benchmark.
- Extended the pre-benchmark from an in-place camera pan to a strategic farthest-point tour of up to ten populated map sectors. Distant geometry is uploaded before driving reaches it, and every authored GPU texture is prepared in yielded batches even on slow hardware instead of deferring all but eight textures into play. Software renderers such as SwiftShader use a bounded two-sector/two-view pass before Low-profile measurement so fallback browsers do not spend minutes rasterizing a hardware-GPU workload.
- Primed WebAudio from the original Play user gesture so procedural noise buffers and the engine graph are not allocated during the first active driving frames.
- Made that audio preparation deterministic: the pre-benchmark now awaits fetch and decode for every native and Logic Vehicle Sound Designer bank, attaches the muted loop voices before Play, and caches procedural ignition/shift/blow-off/backfire buffers instead of allocating them on the first accelerator events.
- Removed the gameplay benchmark from the editor bootstrap path. The editor becomes interactive after its own assets are ready; the complete texture/map tour runs only on Play or Simulate, when it can prepare the final authored level without freezing startup UI.
- Fixed an editor/Play preparation race where a mutable loading-mode flag could turn an already-running lightweight editor warm-up into the full gameplay pre-benchmark. Each request now retains its own mode, so opening the editor cannot inherit a later Play request and unexpectedly compile/tour the level during UI startup.
- Volumetric Lighting is enabled by default while the heavier Cinematic Lens Flares are disabled by default. Both remain independent from every quality preset, including Extreme.
- Separated the expensive volumetric light-shaft pass from cinematic lens flares and authored light bloom/glow. Disabling Volumetric Lighting now preserves cinematic sun optics and visible local-light cues without re-enabling the 36-sample shaft integration.
- Added a separate Cinematic Lens Flares checkbox to Video settings and project rendering defaults. Disabling it skips the advanced sun/local-light optical passes while retaining the cheaper classic flare and light sprites.
- Re-enabled the lightweight front-headlight glow in the bundled DEMO so the front lamps retain the same visible source cue as the rear lamps when cinematic flares are disabled.
- Fixed Path Tracing initialization on scenes containing custom shader materials. Unsupported animated/shader surfaces now stay in a depth-correct raster overlay instead of aborting BVH material packing.
- Path Tracing now shares the engine's only Three.js module graph, removing the duplicate-Three import and its unsafe cross-instance material checks.
- Added Progressive Path Tracing as an explicitly **experimental, not stable** rendering mode. It remains available for continued testing but is not presented as a production-ready alternative to WebGL or Ray Lighting.
- Improved experimental Path Tracing isolation for optical sky geometry, procedural environment sampling, common non-PBR Three.js materials and stationary Editor vehicles. Animated shaders, video textures and moving gameplay actors intentionally retain a raster fallback.
- Reduced repeated progressive-sample resets from the animated day/night light while preserving periodic environment and direct-light updates.
- Extended night authoring with Moon indirect light up to `4×` and a separate Night environment response up to `5×`.
- Upgraded **Surface Layer · preserve PBR** decals from scalar-only matching to real receiver-map reuse. A decal now keeps normal-alpha color layering while reusing the matched surface's normal, roughness, metallic, AO and environment maps, with adjustable receiver base-texture influence and Material Override. Texture objects are referenced rather than cloned, surface matching refreshes after transforms, and the layer remains one lightweight decal draw. Receiver probing now raycasts only meshes, so scene flares/sprites cannot interrupt matching before the road is reached.
- Removed vehicle glow/flare billboards from the SSR ray-source buffer while preserving them in the normal beauty render. Screen-space reflections now sample the real emissive lamp mesh and scene depth instead of mirroring an optical halo that happened to sit behind bodywork.

## Vehicle authoring

- Corrected the shared Cannon drivetrain for native and Logic Player Cars. The Drift preset is now explicitly rear-wheel drive: every wheel is cleared first and engine force is distributed per axle, with `Front drive share` available from `0%` RWD through `50%` AWD to `100%` FWD. Logic Vehicles no longer treated every wheel whose `driven` flag was omitted as powered, which had been applying strong front-axle drive during launch.
- Replaced step-like turbo torque with a persistent spool-pressure model. Turbo contribution, spool-start RPM and response time are editor parameters; boost grows across a broad smooth RPM curve, follows partial throttle and rises/falls over time instead of switching on around one engine speed. The Drift preset retains useful high-gear torque without an instant 2,000-RPM kick.
- Split suspension stiffness and compression/rebound damping into front and rear offsets on top of the existing master controls. Native and Logic Cannon wheels now receive their real axle classification plus independent live values; Drift ships with a firmer front/slightly softer rear balance while all values remain editable and saved per vehicle.
- Added a fourth, configurable Interior camera mode at steering-wheel height for both the native Player Car and Vehicle Logic Elements. The existing camera-cycle action includes it.
- Added persistent External and Interior Player Camera dummies under the native vehicle hierarchy. Both are selectable from the Outliner or directly in the viewport and support the standard translate/rotate gizmos; their authored transforms drive the saved camera configuration while remaining hidden from gameplay renders.
- Reframed the default Interior camera for a left-hand-drive cockpit, aligned with the steering wheel rather than the vehicle centre. Added adjustable filtered G-force head motion, independent fore/aft acceleration response, deterministic road/engine shake and a separately capped speed FOV. Translation, G-force response and vibration are now all off by default; when deliberately enabled they are clamped to a configurable cabin safety range, while speed can add at most +4.5° FOV. Untouched legacy centred presets migrate automatically while manually positioned/rotated cameras are preserved.
- Made the Interior camera rigidly follow the vehicle mount instead of interpolating through world space. Acceleration, braking, jumps and collision shake can no longer leave the eye lagging or sliding around the cabin.
- Extended the mapped **Look Back** action (`V` / gamepad binding) to the Interior camera for native and Logic Element vehicles. The cockpit eye remains exactly on its authored dummy while only its viewing direction turns 180°, then returns forward on release.
- Added complete cockpit steering-wheel animation for native Player Car and Vehicle Logic Elements. The shared Inspector can enable it, override pivot/mesh names and driver side, choose local X/Y/Z or GLB metadata, invert left/right direction, set 180–2160° controller lock, keep a shorter visible lock, and tune response. Settings persist per vehicle and the animation uses the same normalized steering input as the road wheels in Editor/Simulate/Play.
- Added the public-source Blender 5.0+ **Car Wheel GLB Rigger 0.2.2** under `tools/blender 5.0+`, including its Blender-built install ZIP, full GPL-3.0-or-later license, source and smoke test. It detects or accepts an interior steering wheel, preserves its world placement, creates `steering_wheel_pivot > steering_wheel_mesh`, infers left/right driver side, and exports axis, direction, 900°/540° default ranges and up-to-2160° metadata as glTF extras.
- Fixed Blender-generated wheel and cockpit steering pivots looking correct in the `.blend` file but exporting at the vehicle origin because their position was hidden in `matrix_parent_inverse`. Version 0.2.2 now bakes genuine local transforms into the glTF hierarchy: the pivot owns the offset and its mesh child is locally centred. The steering pivot preserves the manually authored object origin and local orientation by default, with bounds-centre placement remaining optional. Re-running Build safely replaces an earlier generated hierarchy without moving authored meshes or leaving a stale pivot that the runtime could detect first.
- Made the visible `steering_wheel_mesh` itself the runtime rotation target. The Blender-exported pivot remains the axle/lock metadata reference, its axis is converted once into mesh-local space, and the mesh rotates around its own authored origin without changing world position even when an older or malformed GLB leaves `steering_wheel_pivot` at the vehicle root or ground.
- Added per-material dynamic dashboard textures. A selected GLB material slot can display Sport, Minimal or Track Telemetry HUD data at a throttled refresh rate and selectable texture resolution. Per-slot edits now split shared glTF material instances first, so assigning a second display no longer replaces or disposes the first.
- Added an emissive, UV-adjustable **HUD / Radio TAB** material surface driven by the same playlist, telemetry, playback, shuffle, volume and bass state as the existing Radio TAB. Its controls are clickable directly on the mesh in Editor and Play.
- Added an interactive YouTube material mode for video and playlist URLs. The mesh provides a visible launcher and opens the official privacy-enhanced `youtube-nocookie` iframe player on click; direct CORS-enabled MP4/WebM material textures continue to use the browser's asynchronous video decoder. Existing YouTube URLs saved under the old direct-video mode migrate automatically.
- Fixed dynamic HUD, Radio, YouTube-launcher and direct-video maps disappearing on dark imported GLB materials. A new non-destructive **Override Base Color with this screen** toggle places the media above the protected original map, temporarily neutralizes material/vertex tint, and restores the exact GLB color, texture, emission and vertex-color state when disabled. **Auto-fit screen UV** now defaults on and projects the complete display through a spare UV channel, fixing imported atlas islands that sampled only a black corner while leaving the GLB's authored UVs untouched. Screen scale, offset and rotation now have separate `dynamic*` values instead of inheriting the original texture's atlas transform, and **Fit screen UV 1:1** resets them instantly. Fixed the Screen UV controls overwriting each other from a stale Inspector snapshot: scale, both offsets and rotation now combine live. Added independent Screen Roughness, Metalness and GPU-uniform Saturation sliders; imported PBR maps are protected underneath rather than multiplying these screen values, and are restored with the original material. YouTube remains an interactive on-mesh launcher because browser cross-origin security prevents copying live iframe frames into WebGL; direct CORS-enabled video renders live on the mesh and now exposes its audio mute control.
- Added exclusive music focus across Radio TAB, menu/loading music, YouTube material players and audible direct-video material surfaces. Starting any one pauses every other music source without resetting its position; starting Radio pauses mesh media and a focus-paused direct video no longer auto-restarts on the next frame. YouTube playback-state integration also reclaims focus when Play is pressed inside the embedded player.
- Added a non-destructive **Car Paint / Vinyl Override** layer above every material slot, including imported GLB materials. It provides manufacturer-style paint and wrap palettes, custom color, metallic brilliance, one coordinated Reflection / Finish control, clear coat, restrained pearl shift and optional reuse of original base-texture detail. Standard materials are promoted temporarily to Physical while the layer is active; disabling it restores the exact original material instance and values. The Inspector displays both layers as a compact stack and locks the underlying scalar controls while the override is active.

## Asset importing

- Temporarily disabled Asset Scout after reviewing the providers' current service terms. Poly Haven assets remain CC0 and commercially usable, but its live API now requires an application-identifying `Referer` or `User-Agent`, which a localhost/static browser editor cannot reliably provide. The two Scout scripts, public editor API, Inspector button, panel and Tools command are no longer loaded or exposed; no shared Three.js import/export library was removed because those components are also required by local GLB/FBX workflows.
- Unified vehicle-rig detection between drag-and-drop import and direct Player Car replacement. Importing the same GLB through either route now creates or updates one Assets entry and applies the same vehicle/skeleton/static classification.
- Unified steering-wheel pivot aliases and 0.2.2 GLB extras with imported vehicle rig metadata, runtime diagnostics and the native/Logic vehicle Inspectors.
- Documented the bundled demo city's asset provenance and credited `Modern City Block` by Sketchfab creator `akselmot` in the README, demo documentation and third-party notices.
- Assets now own keyboard focus independently from the scene viewport. After selecting an Assets card, Delete targets that asset instead of the previously selected viewport object; deleting an imported source also removes ordinary scene instances, restores the native Player Car placeholder and preserves linked Logic Elements with an explicit missing-source placeholder.
- Detailed asset previews now paint a staged loading/progress state before GLB parsing, cancel safely when closed, and always expose the asset size or a calculated resource/metadata estimate. Small and medium GLBs receive lazy thumbnails while very large models remain opt-in through the detailed preview.
- Expanded Outliner thumbnail eligibility to every renderable scene object rather than only objects classified literally as `mesh`.

## Editor performance and persistence

- Added versioned **split project folder** export/import for GitHub-safe large projects. The export writes a tiny `.lkep.json` pointer beside a same-named folder containing a manifest and ordered ~8 MB parts; every part carries exact character/byte lengths and a SHA-256 checksum when Web Crypto is available. Chrome/Edge can write or import the folder directly, while other browsers receive an extract-before-commit ZIP. Hosted Editor and Game transparently fetch, verify and concatenate the parts before the unchanged LKEP parser runs, so embedded levels and portable assets preserve the same round trip without any repository file approaching GitHub's 100 MB limit.
- The normal localhost **★ DEMO** publisher now switches automatically to the split layout at 90 MB and keeps using it on later publications, so republishing cannot silently recreate an oversized `demo-project.lkep.json`. The current 108,598,389-byte demo has been converted into 14 verified parts; the largest is 8,000,000 bytes.
- Increased the Inspector sidebar's default width from 280 to 360 pixels and contained all controls, previews and long labels within the available column. Material/mesh controls no longer overflow beyond the browser edge or require the sidebar to be widened after every refresh.
- Added an editable vehicle radar/minimap to level UI. It draws the live collider world, items, interactions, targets and vehicles on a throttled Canvas 2D overlay without a second WebGL camera; position, size, range, opacity, rotation, shape, layers and refresh rate persist per level and can be previewed from HUD / Level UI.
- Corrected the vehicle radar basis and marker rotations against the engine's real handedness (`+Z` forward, positive yaw steering left, driver-right on `-X`). Forward stays at the top, left steering rotates the map right, right steering rotates it left, and vehicle-right remains at screen-right after every heading change.
- Moved the vehicle radar's untouched default layout into the safe top-left corner with only the viewport's 8 px edge padding. Existing deliberately customized positions remain unchanged, the previous exact `2.2% / 18%` default migrates automatically, and HUD / Level UI retains Left/Top sliders plus a new one-click **Snap to top-left** action.
- Added **UV Lab** to Edit Mesh with a checker/wireframe UV visualizer, draggable UV placement, numeric offset/scale/rotation/padding, imported-UV restore, Planar Top/Front/Side, Cube, Cylinder and Sphere projections, plus a six-direction **Smart Atlas** packed into a padded 3×2 layout. Mapping recipes persist compactly and are regenerated on import; topology-changing atlas modes are protected on skinned and morph meshes.
- Reworked Edit Material and Edit Mesh visual hierarchy with stronger target previews, compact parameter cards, clearer actions and GLB structure summaries.
- Material opacity values that round to a displayed 100% are normalized to a real `1.0` opaque state when no intentional alpha map, cutout or transmission is present. Exact opacity is now shown alongside the percentage.
- Fixed saved materials that claimed `Opacity 1`, `Opaque` and `Standard` while retaining a stale Physical transmission value. Physical-to-Standard conversion now creates the correct material class, old contradictory saves migrate to zero transmission, and moving Opacity to `1` explicitly selects the fully opaque render path.
- Solid-color material previews no longer inherit the texture checker background; valid materials remain readable even when they do not use a base map.
- Separated persistent project identity (`projectName`) from level identity (`trackName`). Saving, loading or renaming a level can no longer silently rename its parent project; existing browser projects migrate from their catalog name on the next save.
- Added a one-time browser-storage identity migration for projects previously named after an active level such as `FPS Playground`. The migration compares the catalog name against embedded levels, the separate Local Storage level library and the currently loaded scene, restores the stable project-level name, updates the active marker and stamps the new identity schema without renaming any level.
- Hardened the identity migration against already-stamped but still contradictory records, including a project ID for Parking Lot displayed as `FPS Playground`. A schema version no longer suppresses repair while the name still matches a level; only an explicit New Project/import/rename choice can intentionally lock a project name that equals a level.
- Hardened Editor, Play-in-Editor and game overlays for short, narrow and resized browser viewports. Project/level management, storage settings, pause settings and movable windows now stay inside the visible safe area and expose internal scrolling instead of cropping their bottom controls.
- Fixed an intermittent Project Levels desynchronization where the loaded editor scene could be FPS Playground while the `ACTIVE` badge still pointed to Parking Lot. The loaded scene identity now repairs the lightweight level index on editor entry and whenever the levels overlay opens.
- Fixed Inspector event listeners accumulating every time the panel was rebuilt. A single checkbox, dropdown or input no longer triggers many duplicate history snapshots after a long editing session.
- Removed duplicate `pointerdown`/focus history captures and stopped Inspector Undo from cloning immutable embedded GLB or texture payloads.
- Save now commits the active text, URL, textarea, select, range or numeric Inspector control before collecting scene state. Values no longer remain visible only in the current input when Save is clicked without first changing focus.
- Removed a redundant complete JSON clone before browser-project persistence and deferred hidden Assets-catalog reconstruction. This materially reduces blocking work for large multi-level projects.
- Rebuilt Developer Performance Debugger telemetry around a dedicated Web Worker and deterministic node-level task slices capped below 2 ms. Resource aggregation, report serialization and autolog transport now leave the main thread; recursive `Box3.setFromObject` scans were removed, automatic deep audits run only while authoring in Editor, and Play/Simulate reuse the cached resource snapshot while realtime frame/error telemetry remains live. This removes the debugger's own 12-second 50–60 ms hitch cadence.
- Fixed real post-benchmark first-use uploads: runtime hooks can create pawn meshes, dashboard widgets, effects and textures, so the pre-benchmark now takes a second resource inventory after those hooks, uploads the expanded texture set and renders one representative of every hidden geometry/material resource before Play.
- Audited the core Three.js playback path against the usual jank causes. The pre-benchmark already compiles scene programs, uploads textures, pre-renders hidden resource variants and tours strategic map sectors; the renderer already caps the effective drawing-buffer ratio at `2×` plus a 4K pixel budget; and the timestamp-derived, clamped delta loop updates simulation, cameras, effects and hooks before the final render.
- Removed continuous garbage pressure from the hottest native/Logic vehicle paths. Camera targets, chase/interior offsets, authored camera quaternions, physics body axes, steering suspension arrays, engine drift contexts, skid transforms and exhaust transforms now reuse stable scratch objects instead of allocating fresh Three.js objects/arrays every frame or physics sub-step.
- Removed the full-project collider-helper rebuild from ordinary viewport, Outliner and Inspector selection changes. Hidden collision dummies now short-circuit before registry synchronization, bounds scans or complex-mesh wireframe generation.
- Bounded automatic 3D thumbnail work to models proven small by import metadata. Heavy or unknown GLBs keep a semantic asset icon, and opening their properties no longer starts parsing automatically; the detailed preview is an explicit, visibly staged action with size and mesh-count context.
- Added `Y` as the shared show/hide command for the interaction cursor in Play Preview and standalone gameplay (`Shift+F1` remains a compatibility shortcut). HUD Radio, telemetry, video and YouTube launcher materials capture pointer input above transparent Editor chrome, raycast inside the actual rendered/letterboxed viewport, use the same spare UV channel plus repeat/offset/rotation shown on rigid, morphed or skinned meshes, and remain clickable through transparent cockpit glass. Every authored dynamic material now builds an invisible interaction proxy from the exact material-slot faces, so GLB material sharing, coplanar geometry and slot-index ambiguity cannot detach its controller from the clickable surface. Authoring a Radio HUD material counts as an explicit radio binding, so playback, track, shuffle, volume and bass actions cannot be silently rejected by a disabled vehicle-level binding. Radio buttons act directly while any non-button area opens the complete Radio TAB; the latest pointer/raycast result is retained in runtime diagnostics for unambiguous troubleshooting.
- Added cockpit interaction super slow-motion while the cursor is active in the Interior vehicle camera. UI painting and mouse input remain real-time while simulation runs at 10%; the feature is disabled for split-screen configurations and every active or pending P2P session, where simulation time always stays at 100%.
- Fixed `Save failed · Local storage unavailable` on large localhost projects. Once a complete local LKEP bridge backup is proven to exist, the redundant multi-level copy in the browser Projects catalog becomes a compact identity manifest instead of competing with the active level for the small LocalStorage quota. The active scene is also stored once rather than duplicated under both the active slot and level-library slot; switching levels safely moves the previous active revision back into its library slot. Workspace and disk saves now run even if the optional browser catalog write fails, and quota errors are reported accurately.
- Fixed Base Color, Normal, Roughness and other material-map drops filling LocalStorage with base64 image data. Material texture files now go directly to the shared IndexedDB asset store, appear in Assets when metadata can be recorded, and material overrides persist only the small blob key required for reload/export.
- Fixed the authored interior vehicle camera appearing to orbit a displaced pivot after repeated full steering rotations. Runtime and editor preview now copy the same complete world position and quaternion from the interior camera dummy, preserving manual gizmo placement without mixing visual and physics headings. Selecting a camera opens its floating preview automatically, which now provides both minimize and close controls.
- Avoided rebuilding the diagnostic event list when no new error, long task or frame hitch has arrived.
